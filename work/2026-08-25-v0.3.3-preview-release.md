# Aura v0.3.3-preview loans/views release

## Goal

Publish the completed ADR-0038 place-based loans and views feature, together
with the ratified ADR-0045 checkpoint and ADR-0049 class-pattern deferment, as
Aura `v0.3.3-preview` and VS Code extension `0.3.4`.

## Release inventory

- Workspace crates, root npm package, and language server: `0.3.3`.
- Release identity: annotated tag `v0.3.3-preview`.
- VS Code extension: `JohnOlafenwa.vscode-aura-lang` version `0.3.4`.
- CLI targets: Linux x86-64, macOS x86-64, and macOS Apple silicon.
- Additional artifacts: static documentation archive and `SHA256SUMS`.
- Publication path: the tag-triggered Release workflow creates a GitHub
  prerelease and publishes the same VSIX to configured extension registries.

## Included changes

- Place identity for local, parameter, receiver, fixed class-field, and fixed
  tuple-position roots.
- Shared and mutable local views, inferred last-use lifetimes, reborrowing,
  parent suspension/resumption, immediate write-through, and exact cleanup.
- Returned views tied to one declared origin with method, trait, generic,
  forwarding, and selected-projection support.
- Explicit shared, mutable, and owned closure captures with repeatability,
  escape, storage, and Transfer enforcement.
- Stable view diagnostics and compiler-backed analysis/LSP/editor support.
- Explicit loan-aware MIR, public MIR validation, direct-native lowering, and
  forced MIR/direct backend parity.
- ADR-0045 ratification and formal ADR-0049 class-pattern deferment.

## Verification

The exact local release-candidate gate is green. `npm run ci` passed 1,881
compiler library tests and 375 CLI integration tests in both ordinary and
instrumented runs, 111 language-server tests at 100% coverage, 27 extension
tests, 340 tutorial fences, 129 verified Manual Aura blocks, and the complete
forced MIR/direct runtime fixture matrix. Exact-candidate hosted CI and
published artifact verification subsequently passed, as recorded below.

The first complete local gate exposed one stale coverage assertion: public
native codegen now rejects an over-arity forged call at common MIR validation,
before the older backend-specific arity branch. The regression expectation was
aligned with the stronger public-boundary diagnostic and is rerun as part of
the release candidate.

The next clean run found four stale `match mut` fixture snapshots. Three now
use the dedicated ownership code `AU3002` for a pattern binding used after its
scrutinee is reassigned. The nested-field case is rejected one statement
earlier by the new overlapping-place loan rule and carries its focused repair
help. The fixtures now pin those implemented diagnostics.

A complete read-only comparison of every check-fail source against its pinned
diagnostic found one additional mismatch: nested `match mut` on the same place
now uses the same overlapping-place wording and repair help. That snapshot is
updated; no other check-fail fixture differed.

The first complete release gate measured the hardened compiler at
100,376/105,227 lines (95.389966%), 6,658/6,953 functions (95.757227%), and
148,497/157,731 regions (94.145729%). This is below the unchanged required
96.30%/97.21%/94.71% floors. The earlier draft incorrectly described 17,254
added lines as production-only (that count included tests), and lowered the
floors without approval. On 2026-09-06 the user explicitly requested that the
original gates be preserved and coverage added. The draft reduction has been
reverted; the required coverage closure was completed before the candidate was
pushed, as recorded below.

Meaningful diagnostic, task-group cleanup, and direct symbolic-contract tests
closed that gap without changing the floors. The final complete local gate
measured 101,387/105,274 lines (96.307730%), 6,760/6,954 functions
(97.210239%), and 149,596/157,785 regions (94.810026%), passing the unchanged
96.30%/97.21%/94.71% requirements.

The first complete retry also exposed a single queue-default CLI watchdog under
extreme parallel process/thread contention. A Daybreak review found no queue
deadlock: the no-timeout implementation uses the immediate `try_recv` path and
the test passed in isolation and concurrent reproductions. The regression now
runs with one requested Aura worker, keeps the same 15-second watchdog, and
passes in the complete ordinary and instrumented suites.
